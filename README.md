# 坦克大战 · 装饰模式扩展版

Java Swing 写的坦克大战小游戏。在原有课程代码基础上修复了编译与运行期问题，并用**装饰者模式（Decorator）**扩展了「特殊砖块」和「掉落物 buff」两套系统——新增一种砖块或一种道具，都只需要加一个装饰器类，不改原有代码。

## 仓库结构

| 路径 | 说明 |
|---|---|
| `untitled/` | **原版代码，完全未改动**（保留作对照，仍带原有两个编译错误） |
| `untitled1/` | **改造版**，修复了报错并加入装饰模式扩展，跑的是这一份 |
| `insect_sprite.png` | 贴图集（34×34 一格） |

两边的差异可以直接 `git diff` 对比。

## 一、原版有哪些问题，怎么解决的

### 1. 编译错误（2 个）

| 位置 | 现象 | 原因 | 解决 |
|---|---|---|---|
| `Fifth/Employee.java` | `ManageSys3` 报「找不到符号: 类 Employee」 | 整个类被注释掉了（`/* ... */` 包住全文） | 按上课代码恢复类的完整定义 |
| `FolderItem/FolderItem.java` | `Folder` 报「找不到符号: 方法 printAll(int)」 | 抽象类只有无参 `printAll()`，`Folder` 调的是 `printAll(level + 1)` | 补成带缩进层级的重载，并让 `File` 同步实现 |

### 2. 运行期问题（能编译，但跑起来会崩或行为不对）

| 问题 | 现象 | 解决 |
|---|---|---|
| `Resourse.getImg()` 空指针 | `getInstance()` 才会加载图片，但 `Tank`/`NPCTank` 直接调静态方法 `getImg()`。若它先被调用，`img` 还是 `null`，画第一帧就抛 NPE | `getImg()` 内部先保证单例已初始化 |
| 资源路径写死 | `new File("insect_sprite.png")` 只在工程根目录启动才找得到，在 `src` 下启动直接 `FileNotFoundException` | 改成候选路径列表 + 从当前目录逐级向上查找（共 5 个位置） |
| 地图路径写死 | 同上，`map1.txt` 在 IDEA 默认工作目录下找不到 | 同样的候选路径机制，并读出绝对路径打印出来便于排查 |
| `Map.loadData` 数组越界 | 地图文件里有空行，`line.split("=")` 得到长度 1 的数组，`strs[1]` 越界 | 跳过空行、`#` 注释行、缺 `=`、坐标非数字的行 |
| `Bullet.isHitTank` 判定错位 | 直接读字段 `x`/`y`，而坦克一旦被装饰器包住，子弹读到的是装饰器自己的坐标（恒为 0），碰撞判定永远失败 | 改走 `getX()`/`getY()`，沿装饰链转发到真正的坦克 |
| `NPCTank.count` 只增不减 | 原版用 `getCount() < 50` 控制刷怪，敌人被打死也不减，于是刷满 50 个后**永远不再刷怪** | 补 `decreaseCount()`，刷怪改为按场上实际数量（上限 6）判断 |
| 线程安全问题 | 游戏线程在给 `ArrayList` 增删元素，EDT 同时在遍历绘制，偶发 `ConcurrentModificationException` | `updateGame()` 和 `paint()` 都加 `synchronized`，互斥访问 |

### 3. 功能缺口（原版能跑但没什么可玩）

原版的 `Block` 只有 `draw()`，子弹不会和砖块碰撞；`Gameprop` 是空壳，连 `draw()` 都是空的；`Decorator` 只转发 `move`/`draw`，`receiveHit` 之类根本没抽出来，套了装饰器也没有任何效果。

所以这次不只是「修 bug」，而是把 `Block`、`Gameprop`、`Decorator` 三个基类的接口补齐（血量、是否挡弹、爆炸半径、掉落列表、伤害拦截、拾取碰撞），装饰模式才有落点。

## 二、游戏实现了哪些功能

### 2.1 装饰者模式：两条独立的装饰链

**① 方块链** —— `BlockDecorator` 本身也是 `Block`，可以继续被包、继续放进地图：

```
Block b = new BlockBrick(x, y);   // 普通砖，1 枪碎
b = new DcrStrongBlock(b);        // 加固砖：外面加 2 层钢板
b = new DcrBombBlock(b);          // 再包一层：变成「会炸的加固砖」
```

| 装饰器 | 效果 | 视觉 |
|---|---|---|
| `DcrStrongBlock` | 加 2 层钢板，要 3 枪才碎（`armor` 记在自己身上，不动内层） | 半透明钢板 + 白色边框 + 四角铆钉 + 剩余层数小方块 |
| `DcrBombBlock` | 碎掉时爆炸，半径 80px 内的敌人被炸死、砖块被震碎，并额外掉 1 个道具 | 红色炸药桶 + 引线火花 |
| `DcrGiftBlock` | 惊喜砖，必掉 2 个道具 | 金色双线边框 + 黄色加号 |

叠加写法由地图文件驱动，**新增特殊砖不用改 `Map`、也不用新增子类**：

```
brick=7,4                    普通砖
brick+strong=7,5             加固砖
brick+bomb=6,4               炸药砖
brick+gift=8,6               惊喜砖
brick+strong+bomb=17,5       又硬又会炸
brick+bomb+gift=7,11         会炸还掉两个道具
```

**② 掉落物 → buff 链** —— 地上一个道具是一个 `Gameprop` 子类，坦克碰到后 `createBuff()` 返回一个装饰器套到玩家身上：

```
Gameprop --createBuff()--> Decorator --套在 Tank 上--> 能力变化
```

| 道具 | 图标 | 效果 | 对应装饰器 |
|---|---|---|---|
| 生命 | 红心 | 立刻 +1 命（不是持续 buff） | 无（`createBuff()` 返回 `null`） |
| 护盾 | 锁 | 挡下 1 次伤害，挡完自动从链上摘掉 | `DcrShield` |
| 加速 | 齿轮 | 移动速度 ×2 | `DcrSpeed` |
| 连发 | 手枪 | 开火冷却 10 帧 → 3 帧 | `DcrRapid` |
| 强化弹 | 扳手 | 子弹更快更大、伤害 1 → 2 | `DcrPower` |
| 增益箱 | 金色宝箱 | 随机给上面 4 种之一 | 转发给随机道具 |
| 陷阱箱 | 爆炸星光 | 减速 50%（负面 buff） | `DcrSlow` |

**关键设计：装饰器不修改被装饰对象的字段。** 加速是「`move()` 时临时 `setSpeed(v*2)`，`finally` 里还原」；连发是自己接管 `fire()`、直接调 `spirite.createBullet()` 绕开内层冷却；强化弹同时覆盖 `createBullet()` 和 `fire()`，所以不管和连发谁套在外面，打出来的都是强化弹。这样摘链时不会留下残留状态。

### 2.2 掉落物从哪来

| 来源 | 掉落规则 |
|---|---|
| 击败敌人 | 28% 掉随机正面道具，12% 掉陷阱箱，其余不掉 |
| `brick+gift` 惊喜砖 | 必掉 2 个随机道具 |
| `brick+bomb` 炸药砖 | 必掉 1 个随机道具 |
| `brick+strong+bomb` | 上面两条叠加，掉 1 个 |

道具在地上存在 520 帧（约 52 秒），最后 90 帧闪烁提示即将消失。

### 2.3 buff 的生命周期

- 每个 buff 由一个 `BuffSlot` 计时，默认 **260 帧（约 26 秒）**
- 到时间用 `Decorator.remove()` 递归找到那一层、把内层接回外层，精确摘链
- 同类 buff 不叠加：捡到新的先把同类型的旧层摘掉，否则链会越套越深
- 死亡复活时 `Decorator.unwrapAll()` 一次性剥干净，还原成最初的 `Tank`
- 左侧 HUD 显示 buff 图标 + 剩余时间进度条（减速用蓝色，正面用绿色）

### 2.4 战斗与地形

| 地形 | 血量 | 挡子弹 | 说明 |
|---|---|---|---|
| 砖块 `brick` | 1 | 是 | 一枪碎，碎掉 +5 分 |
| 石头 `stone` | 不可摧毁 | 是 | 地图边界，挡子弹也挡路 |
| 水 `water` | 不可摧毁 | **否** | 子弹直接飞过 |
| 草丛 `grass` | 不可摧毁 | **否** | 给对手做掩护 |

- 敌军坦克血量 2：普通子弹两发、强化弹一发
- 敌军 AI：`RandomMoving` 随机游走，玩家进入 100px 内切换成 `FollowMoving` 追击（策略模式，原有代码保留）
- 敌军场上上限 6 个，按概率持续刷新，并会主动开火
- 玩家 3 条命，被打中掉 1 命，掉光后回满 3 命、分数清零并复活到出生点
- 分数：打碎砖块 +5，击杀敌人 +10，爆炸击杀 +10

### 2.5 HUD

左上角生命（红心）、右上角分数、左侧 buff 图标 + 倒计时进度条。

## 三、怎么操作

| 按键 | 功能 |
|---|---|
| `↑` `↓` `←` `→` | 改变坦克朝向，**坦克会持续朝该方向自动前进**（撞到边界自动掉头） |
| `空格` | 开火（默认约 1 秒一发，吃到连发 buff 后约 0.3 秒一发） |
| `R` | 重开：生命和分数重置，清空所有 buff |

**小技巧**：先想办法打掉金色边框的惊喜砖拿 buff，再清敌人；炸药砖会连锁震碎周围一圈砖，对付成片的砖墙最省子弹——但注意爆炸也会把旁边的惊喜砖一起炸掉，掉落物还在，只是少吃几枪的分。

## 四、怎么运行

### 方式一：IDEA（推荐）

打开 `untitled1` 目录，运行 `game2025.MainClass`。

### 方式二：命令行（JDK 8+，已在 JDK 21 验证）

```bash
cd untitled1
javac -encoding UTF-8 -d out $(find src -name "*.java")
java -cp out game2025.MainClass
```

> `-encoding UTF-8` 不能省，源码里有中文注释，Windows 默认 GBK 会报「编码 GBK 的不可映射字符」。
>
> 资源文件用了候选路径查找，所以在 `untitled1/`、`untitled1/src/` 或工程根目录下启动都能找到 `insect_sprite.png` 和 `map1.txt`。

### 改地图 / 改外观

- **地图**：`untitled1/map1.txt`，格式 `类型=列,行`（每格 34×34，坐标从 0 开始），支持 `+` 叠加装饰，空行和 `#` 注释会被跳过
- **图标坐标**：`game2025/Icons.java`，所有贴图集坐标集中在这里，换图只改这一处
